# 검증 기록 형식

SKILL.md 6단계(결과 보고)에서 검증 계획이나 보고서를 만들 때 사용한다. 핵심은 **무엇을 어떤 증거 수준으로 확인했는지**를 분리해 적는 것이다.

## 1. 증거 수준

| 수준 | 의미 | 예 |
|---|---|---|
| L0 코드 확인 | 코드를 읽고 경로가 존재함을 확인 | 라우트·핸들러가 연결됨 |
| L1 화면 표시 | 화면이 열리고 구조가 보임 (스크린샷) | 목록 화면 도착 |
| L2 동작 실행 | 행동을 실제로 눌러 결과 화면·상태 변화 확인 | 저장 후 완료 메시지 |
| L3 데이터 확인 | 저장·전송 결과를 재진입·조회·서버 응답으로 확인 | 새로고침 후 값 유지, API 200 응답 |
| L4 실기기/외부 | 실제 기기·실제 외부 서비스에서 확인 | 푸시 알림 수신, 실제 결제 |

반응형 브라우저 확인은 L1~L3 이며 L4(실기기)로 보고하지 않는다. "로딩 화면 도착"은 L1, "데이터 표시 완료"는 L2 이상이다.

## 2. 검증 계획 표

실행 전에 작성한다.

| # | 경로 | 진입점 | 단계 | 기대 결과 | 목표 수준 | 전제 조건 |
|---|---|---|---|---|---|---|
| 1 | 예약 생성 | 홈 → 예약 탭 | 날짜 선택 → 시간 선택 → 확인 | 예약 목록에 "확정" 라벨 | L3 | 테스트 계정, 샘플 데이터 |

## 3. 검증 결과 표

실행 후 작성한다. 한 행에 한 경로.

| # | 경로 | 환경 | 실행한 단계 | 관찰 결과 | 달성 수준 | 판정 | 증거 |
|---|---|---|---|---|---|---|---|
| 1 | 예약 생성 | Chrome 데스크톱, 375px 에뮬레이션 | 날짜·시간 선택 후 확인 | 목록에 확정 표시, 새로고침 후 유지 | L3 | 통과 | `shots/01.png`, 응답 로그 |
| 2 | 예약 취소 | 동일 | 상세 → 취소 | 확인 모달 없이 즉시 취소됨 | L2 | 관찰 | `shots/02.png` |

환경에는 플랫폼, 뷰포트, 계정 종류, 데이터 원천(실제 API/샘플)을 적는다.

## 4. 판정 구분

| 판정 | 기준 |
|---|---|
| 통과 | 기대 결과를 목표 수준에서 확인 |
| 확정 결함 | 같은 단계를 두 번 이상 재현했고 앱 동작이 원인 |
| 관찰 | 한 번 발생했거나 원인이 환경·조작일 수 있음. 재현 절차와 함께 기록 |
| 미검증 | 전제 조건 부족·권한·외부 의존으로 실행하지 못함. 이유를 적는다 |
| 범위 외 | 요청 범위가 아니어서 실행하지 않음 |

조작 문제(잘못된 요소 참조, 불완전한 키 입력, 화면 변경 후 갱신하지 않은 참조)는 결함이 아니라 "관찰"로 두고 재실행한다.

## 5. 복귀·상태 검증 항목

경로마다 아래 중 해당되는 것을 별도 행으로 둔다. 하나를 확인했다고 나머지를 확인한 것으로 보지 않는다.

- 내부 뒤로가기 / 시스템 BACK / 브라우저 뒤로가기 / 모달 닫기 각각의 도착 지점
- 입력 중 취소 시 입력 보존 여부
- 상세에서 목록 복귀 시 스크롤·필터·선택 유지
- 설정: 화면 표시 → 저장 → 재진입 후 유지 → 실제 효과(알림 수신 등)를 각각 확인
- 중복 실행: 저장 중 버튼 연타 시 한 번만 처리되는지

## 6. 보고서 구성

1. 요약: 검증한 경로 수, 통과/결함/관찰/미검증 수
2. 결과 표 (3절)
3. 확정 결함 목록: 재현 절차, 기대, 실제, 영향 범위
4. 미검증 항목과 이유
5. 증거 파일 위치와 실행 환경

"전체 검증 완료"는 모든 계획 행이 통과일 때만 쓴다. 미검증 행이 하나라도 있으면 "N개 경로 중 M개 통과, K개 미검증"으로 적는다.
